GAIN ARCHITECTURAL REVIEW EXECUTIVE SUMMARY • STRATEGIC CONTEXT

Executive Overview: The Paradigm Shift

Moving from "Vibe Coding" to Spec-Driven Engineering

⚠️ Ad-Hoc AI Coding ("Vibe Coding")

  • Prompt & Hope: Jumping straight to code generation from conversational prompts without boundary enforcement.
  • Architectural Drift: Invariants, domain models, and schemas silently mutate across successive AI iterations.
  • Hallucinated Invariants: Unverified assumptions invented by LLMs without validation or regression locks.
  • Fragile Tech Debt: Code velocity accelerates dramatically, but system predictability and enterprise defensibility collapse.

🛡️ Spec-Driven Development (SDD)

  • Spec is the Codebase: The formal specification is the canonical, versioned single source of truth.
  • Code as Disposable Artifact: Code is downstream byproduct synthesized to satisfy machine-verifiable contracts.
  • Deterministic Guardrails: Verifiable schemas, quality rules, and metric definitions gate every phase.
  • Human Authority: Strict sign-off gates required before code generation or backlog issue promotion.
📌 Core Principle (Microsoft Developer Blog Reference)
"As AI coding agents commoditize raw syntax generation, the primary architectural bottleneck shifts from writing code to defining explicit, verifiable specifications that govern behavior."

GAIN ARCHITECTURAL REVIEW SECTION 3: EXECUTION STRATEGY

Thin Vertical Slice Strategy

De-risking Delivery by Proving the Critical Path First

The Anti-Pattern: Horizontal Sprawl

  • Unvalidated Schemas: Building extensive relational models before proving API ingestion ergonomics.
  • Premature UI/Reporting: Designing dashboards prior to verifying rate-limits and pagination boundaries.
  • Accumulating Blind Assumptions: Multi-subsystem integration failures detected late in development.

GAIN's Thin Vertical Slice (Phase 1)

GitHub GraphQL API → Cursor pagination (max 100)
  ↓
gain.github.client → Transport, token auth & rate limits
  ↓
data/raw/ → Immutable JSONL audit archive + Run ID
  ↓
gain.schema & gain.model.pr → Canonical Pydantic normalization
  ↓
gain.metrics.cycle_time → GAIN-PR-001 (Percentiles)
  ↓
data/metrics/*.parquet → Verified analytics & offline demo
💡 Core Strategic Benefit
Phase 1 proved end-to-end telemetry flow, storage, and mathematical accuracy before undertaking Phase 2 (resilience, retries) or Phase 3 (advanced batching & multi-repository cohorts).

GAIN ARCHITECTURAL REVIEW SECTION 5: INTEGRATION PATTERNS

Decoupling External Trackers: Jira as an Adapter

The Trap: Letting Issue Trackers Dictate Architecture

❌ The Jira-Centric Pitfall

  • Domain Model Corruption: Domain models leak proprietary vendor schemas (customfield_10014, Atlassian Document Format).
  • Single Point of Failure: Development workflows halt when Jira API is offline or unauthenticated.
  • Vendor Lock-in: Engineering teams are tightly coupled to external issue trackers.

✅ GAIN's Hexagonal Architecture

  • Internal Domain Entity: CanonicalRequirement is the authoritative model.
  • Decoupled Reference: External systems mapped via ExternalReference (external_system, external_key, external_url).
  • Pure Adapter Pattern: gain.requirements.jira isolates ADF formatting, HTTP transport, and error containment.
🎯 Strategic Outcome
GAIN operates with zero Jira dependency in pure Git/SDD mode, while supporting deterministic bidirectional Jira synchronization when desired.

Executable Contracts & Data Quality Engine

Machine-Verifiable Semantic Guardrails

1. Input & Metric Authority

  • Input Contract: Validates GraphQL query shapes, pagination cursors, and rate-limit budgets.
  • Metric Catalog Authority: Calculations strictly validated against versioned catalog definitions:
catalog = MetricCatalog("docs/metrics/metric-catalog.yaml")
definition = catalog.get("GAIN-PR-001")
if definition["metric_version"] != CycleTimeMetric.metric_version:
    raise BadParameter("Code and Catalog versions mismatch")

2. Programmatic Quality Engine (gain.quality)

  • Semantic Invariants Enforced:
    • merged_at < created_at: ❌ Strictly invalid (negative duration).
    • closed_at < created_at: ❌ Strictly invalid.
    • Duplicate Node IDs: ❌ Detected and flagged.
  • Zero Silent Dropping: Every invalid record is surfaced in structured normalization_report.json.
